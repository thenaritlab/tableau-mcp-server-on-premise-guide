# 💡 5 use case ยอดนิยม

`ส่วนที่ 5 จาก 9`

> แต่ละ use case ต่อยอดจากอันก่อนหน้า ลองทำตามลำดับบน site ทดสอบ พอถึงอันที่ห้าคุณจะได้สคริปต์เดโมที่ทำซ้ำได้ และเห็นชัดว่าโมเดลทำอะไรกับข้อมูลของคุณได้และไม่ได้

ตัวอย่างทั้งหมดสมมติว่ามี published data source ชื่อ **Sales** ใน project ชื่อ **Demo Company** มีฟิลด์เช่น `Order Date`, `Region`, `Category`, `Sales`, `Profit`, `Quantity`

## 1. ค้นหาและทำความเข้าใจเนื้อหา — 🟢 พื้นฐาน

**เป้าหมายทางธุรกิจ** ลดเวลาที่นักวิเคราะห์ใช้ไล่หา workbook หรือ data source ที่ถูกต้อง
**ใครใช้** ทุกคน โดยเฉพาะพนักงานใหม่
**tool ที่เกี่ยวข้อง** `search-content`, `list-workbooks`, `list-datasources`, `list-fields`

### ตัวอย่าง prompt

- "Workbook ไหนบ้างที่เกี่ยวกับ *inventory*"
- "แสดง data source ใน project Demo Company พร้อมชื่อเจ้าของ"
- "อธิบายฟิลด์ใน data source Sales เป็นภาษาง่ายๆ"

### ขั้นตอน

1. ถาม *"ฉันมีสิทธิ์เข้าถึง data source อะไรบ้าง"* โมเดลเรียก `list-datasources`
2. ถาม *"อธิบาย data source Sales"* โมเดลเรียก `list-fields` แล้วสรุป dimension, measure และ calculated field
3. ถาม *"Workbook ไหนใช้ data source นี้"* ถ้าเปิด Metadata API ไว้ โมเดลจะตาม lineage ได้

**ผลลัพธ์ที่คาดหวัง** รายการสั้นๆ พร้อมชื่อ project เจ้าของ วันที่อัปเดตล่าสุด และ data dictionary ภาษาคน

**ข้อควรระวัง** คำอธิบายฟิลด์ดีได้เท่าที่ผู้สร้างพิมพ์ไว้ใน Tableau เท่านั้น ให้เพิ่ม description และ alias ใน published data source มิฉะนั้น AI จะเดา การค้นหาเนื้อหาถูกจำกัดด้วยสิทธิ์ ดังนั้น workbook ที่ "หายไป" มักหมายถึงผู้ใช้มองไม่เห็น

## 2. ถามคำถามกับ data source — 🟢 พื้นฐาน

**เป้าหมายทางธุรกิจ** ตอบคำถามแบบ "X แยกตาม Y เท่าไร" โดยไม่ต้องเปิด dashboard
**ใครใช้** ผู้จัดการ ฝ่ายขาย ฝ่ายปฏิบัติการ
**tool ที่เกี่ยวข้อง** `query-datasource` (VizQL Data Service)

### ตัวอย่าง prompt

- "ยอดขายและกำไรรวมแยกตามภูมิภาค ปี 2025"
- "สินค้า 10 อันดับแรกตามจำนวนที่ขายได้ในภูมิภาค West ไตรมาสที่แล้ว"
- "แนวโน้มยอดขายรายเดือนของหมวด Furniture เทียบ 2024 กับ 2025"

### ขั้นตอน

1. โมเดลอ่าน metadata ของฟิลด์ (จาก use case 1) แล้วสร้าง VDS query: ฟิลด์ การรวมค่า ตัวกรอง
2. เรียก `query-datasource` แล้วได้ตารางเล็กๆ กลับมา
3. จัดรูปแบบตารางพร้อมข้อสังเกตหนึ่งหรือสองข้อ

**ผลลัพธ์ที่คาดหวัง** ตารางไม่กี่แถวพร้อมตัวเลข และโมเดลระบุว่าใช้ data source และตัวกรองอะไร

**ข้อควรระวัง** ขอ aggregate เสมอ "ขอ order ทั้งหมด" จะพยายามดึงข้อมูลระดับแถวจน timeout หรือ context เต็ม ตัวกรองวันที่ผิดพลาดบ่อยที่สุด ตรวจว่าโมเดลใช้ปฏิทินบัญชีที่ถูกต้อง ช่วงแรกควรเทียบตัวเลขกับ dashboard ทุกครั้ง

> [!TIP]
> **กำหนดความคาดหวังใน system prompt**
>
> ใน portal ที่สร้างเอง (ส่วนที่ 6) สั่งโมเดลให้ระบุ data source และตัวกรองเสมอ ใน Claude Desktop ใช้ project instruction ทำให้ทุกคำตอบตรวจสอบย้อนหลังได้

## 3. สรุปผู้บริหารจาก dashboard — 🔵 ระดับกลาง

**เป้าหมายทางธุรกิจ** เปลี่ยน dashboard รายสัปดาห์เป็นสรุปเขียนสำหรับผู้บริหาร
**ใครใช้** นักวิเคราะห์ที่เตรียมรายงานให้ผู้บริหาร
**tool ที่เกี่ยวข้อง** `get-view-data`, `get-view-image`, `query-datasource`

### ตัวอย่าง prompt

- "สรุป dashboard *Sales Overview* เป็น 5 ข้อสำหรับ CEO"
- "เทียบเดือนนี้กับเดือนที่แล้ว และเน้นสิ่งที่เปลี่ยนเกิน 10 เปอร์เซ็นต์"
- "เขียนสรุปทั้งภาษาไทยและอังกฤษ"

### ขั้นตอน

1. ให้โมเดลดึงข้อมูลของ view (`get-view-data`) ไม่ใช่แค่ภาพ ภาพช่วยให้อธิบาย layout ได้ ข้อมูลให้ตัวเลขจริง
2. ขอการเปรียบเทียบ โมเดลอาจเรียก `query-datasource` เพิ่มเพื่อดึงช่วงเวลาก่อนหน้า
3. ขอรูปแบบผลลัพธ์ที่ต้องการ (bullet, อีเมล, โน้ตสไลด์)

**ผลลัพธ์ที่คาดหวัง** เรื่องเล่าสั้นๆ พร้อมตัวเลขจริง ทิศทางการเปลี่ยนแปลง และประโยค "สิ่งที่ต้องจับตา"

**ข้อควรระวัง** `get-view-data` คืนข้อมูลสรุปเบื้องหลังของ sheet บน dashboard ที่หนาแน่นให้เลือก sheet เฉพาะ ภาพมีประโยชน์กับคำถามเรื่อง layout แต่กิน token มาก อย่าปล่อยให้โมเดลแต่งสาเหตุ สั่งให้แยก "อะไรเปลี่ยน" ออกจาก "สาเหตุที่เป็นไปได้"

## 4. Admin insight และงานดูแลระบบ — 🔵 ระดับกลาง

**เป้าหมายทางธุรกิจ** รักษา server ให้สะอาดและใช้ลิขสิทธิ์คุ้มค่า โดยไม่ต้องเขียน SQL กับ repository
**ใครใช้** ผู้ดูแล Tableau Server
**tool ที่เกี่ยวข้อง** tool group admin (`get-stale-content-report`, `list-extract-refresh-tasks`, รายการผู้ใช้และสิทธิ์), `list-workbooks`

### ตัวอย่าง prompt

- "Workbook ไหนไม่มีคนดูใน 180 วัน จัดกลุ่มตาม project และเจ้าของ"
- "แสดง extract refresh task ที่ล้มเหลวสัปดาห์นี้พร้อม data source"
- "ร่างอีเมลถึงเจ้าของเนื้อหาที่ไม่ได้ใช้ ขอให้ archive หรือยืนยัน"

### ขั้นตอน

1. รันรายงาน stale content ผ่าน AI ขอเป็นตารางจัดกลุ่มตามเจ้าของ
2. ขอ refresh task ที่ล้มเหลว แล้วเชื่อมโยงกับเจ้าของกลุ่มเดียวกัน
3. ให้โมเดลร่างข้อความติดต่อ แต่คุณเป็นคนส่งเอง ให้มนุษย์อยู่ที่ปุ่มส่งเสมอ

**ผลลัพธ์ที่คาดหวัง** สองตารางและร่างอีเมลที่คัดลอกไปใช้ได้

**ข้อควรระวัง** tool ด้าน admin ต้องการตัวตนระดับ site หรือ server administrator เมื่อใช้ OAuth คือ admin ที่ล็อกอิน เมื่อใช้ Direct Trust ตั้ง `JWT_SUB_CLAIM` เป็น admin ได้เฉพาะในระบบที่ล็อกดาวน์แล้วเท่านั้น พิจารณาใช้ `INCLUDE_TOOLS` ให้ admin ได้ group admin ส่วนคนอื่นได้ group `datasource` โดยรัน MCP สองตัวคนละพอร์ต

## 5. การวิเคราะห์หลายขั้นแบบ agentic พร้อม lineage — 🟣 ขั้นสูง

**เป้าหมายทางธุรกิจ** สืบค้นคำถามทางธุรกิจตั้งแต่ต้นจนจบ: หาแหล่งข้อมูลที่ถูกต้อง query หลายมุม ตรวจว่าตัวเลขมาจากไหน แล้วให้ข้อเสนอแนะ
**ใครใช้** นักวิเคราะห์อาวุโส consultant ที่ทำ proof of concept
**tool ที่เกี่ยวข้อง** ทั้งหมดข้างต้น บวก tool ด้าน lineage/metadata รันใน Claude Code, Gemini CLI หรือ portal ที่สร้างเอง ซึ่งโมเดลเรียก tool ได้หลายขั้นต่อหนึ่งรอบ

### ตัวอย่าง prompt

> "อัตรากำไรในภูมิภาค Central ลดลงไตรมาสที่แล้ว ใช้ data source Sales หาว่า category และ sub-category ไหนเป็นตัวฉุด ตรวจว่าส่วนลดเพิ่มขึ้นหรือไม่ ยืนยันว่า data source Sales สร้างจากตารางฐานข้อมูลใด แล้วสรุปเป็นรายงานหนึ่งหน้าพร้อมข้อเสนอแนะ"

### ขั้นตอน

1. **สำรวจ** โมเดลแสดงรายการฟิลด์และ lineage (`get-datasource-metadata`, tool ด้าน lineage) และรายงานตารางต้นทาง
2. **แยกส่วน** query กำไรตาม category แล้ว sub-category แล้วอัตราส่วนลด แต่ละอันเป็น `query-datasource` แยกกัน
3. **ตรวจสอบ** เทียบยอดรวมกับ sheet ของ dashboard ผ่าน `get-view-data`
4. **สังเคราะห์** เขียนข้อค้นพบพร้อมตัวเลข วิธีการ และข้อจำกัด

**ผลลัพธ์ที่คาดหวัง** ข้อค้นพบที่มีโครงสร้าง: หัวข้อหลัก ตารางหลักฐาน วิธีการ (query อะไรบ้าง) ข้อจำกัด ข้อเสนอแนะ

**ข้อควรระวัง** จำกัดจำนวนรอบการเรียก tool (portal ในส่วนที่ 6 ใช้ 8) มิฉะนั้นโมเดลที่สับสนอาจวนลูป ให้นิยาม "อัตรากำไร" ที่ชัดเจนหาก data source ไม่มี calculated field สำหรับมัน ให้มนุษย์ตรวจทานเสมอ โมเดลเก่งเลขคณิตกับข้อมูลที่ได้กลับมา แต่ไม่รู้ข้อยกเว้นทางธุรกิจของคุณ

> [!TIP]
> **เปลี่ยนเป็นเดโมที่ทำซ้ำได้**
>
> บันทึก prompt ทั้งห้าเป็น project instruction ของ Claude หรือ `GEMINI.md` ของ Gemini พร้อมชื่อฟิลด์ของ Demo Company เดโมลูกค้า 15 นาทีจะเดินเส้นทางเดิมได้ทุกครั้ง
